# 会员管理需求规格书

> 模块优先级：P0（会员业务核心，活动/营销/商城均依赖会员体系）  
> 日期：2026-08-04  
> 关联文档：用户管理需求规格书、会员分层管理模块需求规格书

## 一、模块目标

### 1.1 模块定位

会员管理是连心的**会员业务中枢**，管理会员从入会到退会的全生命周期。核心职责：

1. **会员档案管理**：会员画像、标签、自定义字段、会员卡、分层调整与日志
2. **会员类型管理**：类型定义（内置"普通会员"+自定义类型）、会费标准、类型权益、入会申请表配置、类型转换
3. **会员等级管理**：等级体系、晋级/降级规则、等级权益、升级礼包
4. **会员分层管理**：RFM模型配置（支持交易型/活动型/自定义指标模板）与分层结果（详见《会员分层管理模块需求规格书》）
5. **入会管理**：入会审批、退会管理，驱动用户状态流转

> **范围说明**：本模块聚焦会员业务管理。用户身份注册、登录、手机号管理、账号注销/合并、游客兴趣分层和登录用户活跃分层等，见《用户管理需求规格书》。

### 1.2 核心目标

| 目标 | 衡量指标 | 目标值 |
|-|-|-|
| 入会流程闭环 | 入会申请→审批→生效全流程在线化 | 100% |
| 会员数据完整度 | 会员有类型+等级+到期日的比例 | ≥95% |
| 等级自动升降级 | 符合条件的会员自动升降级覆盖率 | ≥90% |
| 会费续费率 | 到期会员按时续费比例 | ≥70% |
| 会员档案可追溯 | 分层/等级/类型变更100%有日志 | 100% |

### 1.3 核心原则

| 原则 | 说明 |
|-|-|
| **类型×等级双维度** | 会员类型决定基本权益和会费标准，等级决定差异化权益，两者正交组合 |
| **等级自动为主、手动为辅** | 等级以自动计算规则为主，管理员可手动调整但需备注原因 |
| **入会审批按类型配置** | 审批模式按会员类型独立配置（免审批/单人审批/双人审批），审批通过后用户状态自动变更为会员 |
| **退会可恢复** | 退会后用户状态回退为登录用户，历史会员记录保留，可重新入会 |
| **会费与权益联动** | 会费到期未续费→权益自动失效→用户状态回退，续费后恢复 |
| **分层独立于等级** | 分层（RFM）是运营分析维度，等级是权益维度，两者独立计算 |

## 四、业务规则

### 4.1 会员档案

#### 4.1.1 会员画像

会员画像是会员详情页的核心，聚合多维度数据形成完整会员视图：

| 数据维度 | 数据来源 | 展示内容 |
|-|-|-|
| 基本信息 | user_base | 姓名、手机号、头像、注册时间、注册渠道 |
| 会员信息 | user_member_ext | 会员类型、等级、成长值、到期日、入会时间 |
| 分层信息 | 分层计算引擎 | 当前分层（高价值/活跃/沉睡/流失等）、分层变化趋势 |
| 标签信息 | UserTag | 所有标签（系统/规则/自定义），按分类展示 |
| 行为时间线 | 活动管理+商城+消息 | 活动 participation、消费记录、消息互动，按时间倒序 |
| 自定义字段 | UserCustomField | 按机构配置的自定义字段值 |
| 各端登录记录 | UserDevice | App/小程序/H5/网站的登录和活跃情况 |

#### 4.1.2 标签管理

标签同时具有**两个正交属性维度**，每个标签创建时需同时指定：

**维度一：按来源分类（决定创建/删除权限）**

| 来源类型 | 说明 | 创建者 | 可删除 |
|-|-|-|-|
| **系统标签** | 系统自动生成，如"新用户""已入会""已到期" | 系统 | 否 |
| **规则引擎标签** | 规则引擎自动打标，如"高意向""沉睡预警" | 规则引擎 | 停用规则后可删 |
| **自定义标签** | 管理员手动创建，如"理事会""赞助商""VIP客户" | 管理员 | 是（需确认无用户使用） |

**维度二：按语义分类（决定展示分组和筛选）**

| 语义类型 | 说明 | 示例 |
|-|-|-|
| **身份标签** | 描述用户身份属性 | 已入会、理事会成员、赞助商 |
| **行为标签** | 描述用户行为特征 | 高频活跃、活动达人、沉睡用户 |
| **状态标签** | 描述用户当前状态 | 新用户、已到期、待续费 |

> **两个维度的关系**：来源决定"谁创建、谁能删"，语义决定"在详情页哪个分组展示、在列表中按什么维度筛选"。例如"已入会"= 系统标签（来源）+ 身份标签（语义）；"沉睡预警"= 规则引擎标签（来源）+ 状态标签（语义）。

**标签规则：**

| 规则 | 说明 |
|-|-|
| 标签数量 | 每个用户最多50个标签（系统标签+规则标签+自定义标签合计） |
| 标签去重 | 同一用户同一标签只允许存在一条 |
| 标签互斥 | 可配置互斥标签组（如"高价值"和"流失"互斥，打一个自动移除另一个） |
| 自动标签不可手动移除 | 规则引擎打的标签只能由规则引擎移除，管理员可查看但不能手动删 |
| 标签颜色 | 每个标签可配置颜色，在列表和详情页按颜色区分 |

#### 4.1.3 自定义字段

**字段类型（9种）：**

| 类型 | 说明 | 示例 |
|-|-|-|
| 文本 | 单行文本 | 职业、公司名称 |
| 长文本 | 多行文本 | 备注 |
| 数字 | 数值 | 年收入 |
| 日期 | 日期选择 | 生日 |
| 单选 | 下拉选择一个 | 性别、学历 |
| 多选 | 下拉选择多个 | 兴趣领域 |
| 布尔 | 是/否 | 是否为志愿者 |
| 附件 | 文件上传（图片/PDF等） | 会员证件照、身份证明 |
| 签名 | 手写签名采集 | 入会协议签署 |

**字段配置：**

| 配置项 | 说明 |
|-|-|
| 字段名称 | 显示名称（如"职业"） |
| 字段标识 | 英文标识（如"occupation"），系统内部使用 |
| 字段类型 | 文本/长文本/数字/日期/单选/多选/布尔/附件/签名 |
| 是否必填 | 注册/入会时是否强制填写 |
| 是否可搜索 | 是否出现在用户列表的筛选条件中 |
| 可见性 | 哪些角色可见（管理员可见/用户本人可见/公开） |
| 排序权重 | 在详情页中的显示顺序 |
| 单选/多选选项 | 如适用，配置可选项列表 |

**自定义字段约束：**

| 约束 | 说明 |
|-|-|
| 数量上限 | 每个机构最多30个自定义字段 |
| 标识唯一 | 同一机构内字段标识不可重复 |
| 类型不可变更 | 字段创建后类型不可修改（避免数据不兼容） |
| 可停用不可删除 | 字段可停用（不展示不校验），但历史数据保留不删除 |

#### 4.1.4 会员卡管理

会员卡采用**类型×等级**双维度配置：每个会员类型配置基础卡面模板，每个等级在类型模板基础上叠加差异化样式。最终卡面 = 类型基础模板 + 等级差异化样式。

**类型级卡面配置（基础模板）：**

| 配置项 | 说明 |
|-|-|
| 基础背景色 | 卡片底色色系（如蓝色系/金色系/深色系） |
| Logo位置 | 机构Logo在卡面上的位置和大小 |
| 卡片比例 | 卡面宽高比（标准16:9或竖版3:4） |
| 卡面信息布局 | 姓名/类型/等级/到期日/编号的位置排列规则 |

**等级级卡面配置（差异化叠加）：**

| 配置项 | 说明 |
|-|-|
| 卡面图案 | 在类型底色基础上叠加的图案/纹理（如渐变/花纹/几何图形） |
| 颜色深浅 | 同类型不同等级的颜色深浅区分（如银卡浅灰、金卡金色、钻石卡深蓝） |
| 等级标识 | 卡面上的等级图标/勋章/文字标识 |
| 自定义卡面 | 支持上传完整自定义卡面图片，覆盖类型模板 |

**卡面信息：** 会员姓名、会员类型、等级、到期日、会员编号

**发放方式：** 入会审批通过后自动生成电子会员卡，推送到用户端App/小程序

**展示渠道：** App个人中心、小程序个人中心、H5个人页

**二维码：** 会员卡背面生成动态二维码，用于线下核验身份（防截图，每60秒刷新）

**权益关联：** 点击会员卡可查看当前类型+等级对应的完整权益列表

**失效处理：** 会员到期/退会后，卡面变灰显示"已失效"，二维码停止更新

#### 4.1.5 手动分层调整

| 规则 | 说明 |
|-|-|
| 操作入口 | 会员详情页 → 分层信息区 → "手动调整"按钮 |
| 覆盖机制 | 手动调整后，覆盖自动计算结果，直到下次手动取消覆盖 |
| 必填备注 | 调整时必须填写原因（如"高价值客户需重点维护""活动积极分子"） |
| 操作日志 | 记录操作人、时间、原分层、新分层、备注原因 |
| 覆盖标记 | 手动调整的分层在详情页标注"手动调整"标签，与自动计算区分 |
| 取消覆盖 | 管理员可取消手动覆盖，恢复自动计算分层 |

#### 4.1.6 分层变化日志

| 字段 | 说明 |
|-|-|
| user_id | 会员ID |
| old_layer | 变更前分层 |
| new_layer | 变更后分层 |
| change_source | 变更来源：auto_calculate（自动计算）/ manual_adjust（手动调整） |
| operator_id | 操作人（手动调整时记录） |
| remark | 备注（手动调整时填写） |
| changed_at | 变更时间 |

> 日志在会员详情页按时间倒序展示，支持按变更来源筛选。

### 4.2 会员类型管理

#### 4.2.1 类型定义与配置

**内置类型与自定义类型：**

| 类型 | 说明 | 可编辑 | 可删除 |
|-|-|-|-|
| 普通会员 | 系统内置的唯一类型，新机构初始化时自动创建 | 是 | 是（需确认无在用会员） |
| 自定义类型 | 管理员可创建任意自定义类型 | 是 | 是（需确认无在用会员） |

> 不预设"个人/团体/学生/荣誉"等类型。不同社团的会员类型结构差异大，由管理员根据实际需求自主创建。系统只内置1个"普通会员"类型作为默认，管理员可编辑其名称、配置，甚至删除（需确认无在用会员）。

**类型配置项：**

| 配置项 | 说明 |
|-|-|
| 类型名称 | 显示名称（如"普通会员"） |
| 类型标识 | 英文标识（如"regular"） |
| 入会条件 | 是否需要审核、是否需要缴费、是否需要推荐人 |
| 审批流程 | 免审批 / 单人审批 / 双人审批（按类型独立配置） |
| 入会申请表 | 配置该类型的入会申请表单字段（详见4.2.5） |
| 是否启用 | 启用/停用，停用后不可新建该类型会员 |
| 排序权重 | 在类型选择列表中的展示顺序 |

#### 4.2.2 会费标准配置

**基础配置：**

| 配置项 | 说明 |
|-|-|
| 收费模式 | 免费 / 年费 / 月费 / 一次性 |
| 金额 | 收费金额（币种：港币HKD，不支持多币种） |
| 缴费周期 | 年费→每年缴费，月费→每月缴费，一次性→入会时缴清 |
| 续费提醒 | 到期前X天自动提醒（短信/APP推送/社群消息） |
| 宽限期 | 到期后X天内仍可续费，超过宽限期自动退会 |

**优惠政策配置（通用，按类型绑定）：**

| 配置项 | 说明 |
|-|-|
| 优惠类型 | 折扣比例 / 减免金额 / 免首月 / 免首年 |
| 折扣比例 | 如8折、9折（百分比） |
| 减免金额 | 如减50港币（固定金额） |
| 生效条件 | 可配置生效条件（如新会员首年优惠、续费优惠等） |

| 绑定类型 | 优惠政策绑定到具体的会员类型，不同类型可配置不同优惠 |

> 优惠政策不写死任何特定类型（如"学生半价"），而是由管理员为任意会员类型灵活配置。

**会费与会员状态联动：**

```
会费到期 → 进入宽限期（保留会员权益） 
→ 宽限期结束未续费 → 自动退会（用户状态回退为登录用户，权益失效）

```

### 4.4 会员分层管理

会员分层是运营分析维度，独立于会员等级（权益维度）。系统根据用户行为数据，按照配置的规则自动计算分层结果，并驱动自动化运营。

> 完整的分层业务规则、数据模型和计算引擎详见《会员分层管理模块需求规格书》。本节聚焦配置规则、自动打标机制和管理后台交互。

#### 4.4.1 会员分层概述

会员分层是运营分析维度，独立于会员等级（权益维度）。系统根据会员行为数据，按照配置的RFM规则自动计算分层结果，并驱动自动化运营。

> **分层范围说明**：本节仅管理**会员**的分层（RFM模型）。游客兴趣分层和登录用户活跃分层的配置见《用户管理需求规格书》4.6 用户分层管理。用户状态变化时（游客→登录→会员），分层模型自动切换，旧分层历史保留可追溯。

**会员RFM分层级别：**

| 分层 | 默认定义 | 运营动作方向 |
|-|-|-|
| 高价值会员 | 综合得分≥4.0，近期活跃+高频+高贡献 | 专属权益、优先体验、VIP服务 |
| 潜力会员 | 综合得分3.0-3.9，近期活跃但频次/贡献中等 | 提频引导、消费升级 |
| 稳定会员 | 综合得分2.0-2.9，有活跃但频率和贡献一般 | 保持活跃、防止下滑 |
| 沉睡会员 | 综合得分1.0-1.9，近期不活跃 | 唤醒关怀、限时优惠 |
| 流失会员 | R=1且F=1且M=1，长期无任何行为 | 流失挽回或标记归档 |

#### 4.4.2 RFM模型配置规则

RFM是会员分层的核心模型，三个维度均可独立配置权重、评分阈值和统计指标。

**指标模板配置（关键设计）：**

连心客户类型差异大（交易型/非交易型/混合型），RFM三维度支持自定义选择统计指标。系统预置两套模板，也支持管理员自定义组合：

| 模板 | 适用客户 | R维度统计指标 | F维度统计指标 | M维度统计指标 |
|-|-|-|-|-|
| 交易型 | 有商城/收费活动的社团 | 最近一次消费时间 | 消费次数 | 消费金额（HKD） |
| 活动型 | 纯社团/协会/居委会 | 最近一次活动参与时间 | 活动参与次数 | 活动贡献度（签到+1/分享+2/邀新+3） |
| 自定义 | 混合型或有特殊需求 | 从可选指标中自选 | 从可选指标中自选 | 从可选指标中自选 |

**可选指标池：**

| 维度 | 可选统计指标 | 说明 |
|-|-|-|
| R（最近活跃） | 最近消费时间 / 最近活动参与时间 / 最近登录时间 / 最近内容互动时间 | 取所选指标中最近的一次 |
| F（频次） | 消费次数 / 活动参与次数 / 内容互动次数 / 登录次数 | 支持多选，加权求和（每个指标可设权重） |
| M（价值贡献） | 消费金额(HKD) / 活动费用(HKD) / 会费(HKD) / 捐赠金额(HKD) / 活动贡献积分 | 支持多选，加权求和（金额类直接相加，积分类按比例折算） |

> 管理员配置时先选模板（交易型/活动型/自定义），再在每个维度中选择具体统计指标。选择"自定义"模板时可自由组合任意指标。模板切换后，评分阈值需重新配置。

**维度权重配置：**

| 维度 | 含义 | 默认权重 | 可配范围 |
|-|-|-|-|
| R (Recency) | 最近一次活跃距今天数（按所选指标统计） | 40% | 10%-80% |
| F (Frequency) | 观察期内活跃频次（按所选指标加权求和） | 30% | 10%-80% |
| M (Monetary/Value) | 观察期内贡献度（按所选指标加权求和） | 30% | 10%-80% |

> 三维度权重之和必须=100%，前端实时校验。

**评分阈值配置（每维度1-5分）：**

> 评分阈值随所选指标类型自动适配。选择"交易型"模板时，M维度以金额(HKD)为单位；选择"活动型"模板时，M维度以贡献积分 为单位；选择"自定义"时，管理员手动设置阈值单位。以下为"交易型"模板默认值，其他模板需根据实际指标重新配置。

| 维度 | 评分 | 交易型默认条件 | 活动型默认条件 | 可配置项 |
|-|-|-|-|-|
| R（越小越好） | 5 | ≤7天 | ≤7天 | R_5阈值（1-365天） |
| | 4 | 8-14天 | 8-14天 | R_4上限 |
| | 3 | 15-30天 | 15-30天 | R_3上限 |
| | 2 | 31-60天 | 31-60天 | R_2上限 |
| | 1 | >60天 | >60天 | R_1下限 |
| F（越大越好） | 5 | ≥8次 | ≥8次 | F_5阈值（0-100次） |
| | 4 | 5-7次 | 5-7次 | F_4范围 |
| | 3 | 3-4次 | 3-4次 | F_3范围 |
| | 2 | 1-2次 | 1-2次 | F_2范围 |
| | 1 | 0次 | 0次 | F_1 |
| M（越大越好） | 5 | ≥HKD 2000 | ≥60分 | M_5阈值（0-100000） |
| | 4 | HKD 1000-1999 | 40-59分 | M_4范围 |
| | 3 | HKD 500-999 | 20-39分 | M_3范围 |
| | 2 | HKD 1-499 | 1-19分 | M_2范围 |
| | 1 | HKD 0 | 0分 | M_1 |

**分层定义配置：**

| 分层 | 默认得分区间 | 额外条件 | 可配置项 |
|-|-|-|-|
| 高价值会员 | ≥4.0 | R≥4 且 (F≥4 或 M≥4) | 得分阈值（2.0-5.0）、分层名称可自定义 |
| 潜力会员 | 3.0-3.9 | R≥3 | 得分阈值（1.5-4.5）、分层名称可自定义 |
| 稳定会员 | 2.0-2.9 | — | 得分阈值（1.0-3.5）、分层名称可自定义 |
| 沉睡会员 | 1.0-1.9 | R≤2 | 得分阈值（0.5-2.5）、分层名称可自定义 |
| 流失会员 | — | R=1 且 F=1 且 M=1 | 固定条件，不可配置 |

**计算周期配置：**

| 参数 | 说明 | 默认值 | 可配范围 |
|-|-|-|-|
| RFM观察期 | 统计行为数据的时间窗口 | 90天 | 30-365天 |
| 计算频率 | 批量计算执行周期 | 每日 | 每日/每周/每月 |
| 沉睡覆盖天数 | R=1且超此天数直接标沉睡（绕过综合得分） | 30天 | 7-180天 |

#### 4.4.3 自动计算与打标机制

系统根据配置的规则，自动完成分层计算、标签同步和事件推送：

**计算触发机制：**

| 分层模型 | 触发方式 | 计算延迟 | 说明 |
|-|-|-|-|
| 会员RFM分层 | 定时批量任务 | ≤1小时 | 每日/每周/每月凌晨执行，全量重算 |

> 游客兴趣分层和登录用户活跃分层的计算触发机制见《用户管理需求规格书》4.6。

**自动打标流程：**

```
1. 数据采集
   └─ 会员：按所选RFM指标模板采集数据
      ├─ 交易型：商城消费记录 + 活动缴费记录 + 会费缴纳记录
      ├─ 活动型：活动签到记录 + 分享记录 + 邀新记录
      └─ 自定义：按管理员所选指标采集对应数据

2. 分层计算
   ├─ 按配置的阈值和权重计算各维度得分（R/F/M各1-5分）
   ├─ 综合得分 = R×R权重 + F×F权重 + M×M权重
   └─ 根据分层定义表确定分层级别（高价值/潜力/稳定/沉睡/流失）

3. 分层更新与打标
   ├─ 写入 user_member_ext.rfm_layer
   ├─ 分层标签自动同步到用户标签体系（作为"系统标签"，来源=系统，不可手动删除）
   └─ 会员详情页展示当前分层 + 分层来源标记（自动计算 / 手动调整）

4. 变化检测与事件推送
   ├─ 对比本次计算结果与上次分层
   ├─ 有变化 → 写 LayerChangeLog
   ├─ 推送 segment_change 事件 → 规则引擎
   └─ 规则引擎消费事件 → 触发自动化运营动作
       例：稳定→沉睡 → 触发"沉睡唤醒"规则 → 发送关怀消息 + 优惠券
       例：沉睡→稳定 → 触发"回归欢迎"规则 → 发送欢迎消息
       例：潜力→高价值 → 触发"高价值识别"规则 → 推送专属权益
```

**分层与标签的关系：**

| 项目 | 分层 | 标签 |
|-|-|-|
| 来源 | 系统自动计算（RFM/活跃/兴趣模型） | 系统/规则引擎/管理员手动 |
| 性质 | 运营分析维度，每用户同一时刻只有1个分层 | 可多个共存 |
| 变更方式 | 系统自动计算或管理员手动覆盖 | 规则引擎自动打标或管理员手动打标 |
| 用途 | 驱动规则引擎人群筛选和自动化触发 | 画像描述、列表筛选、营销触达 |

> 分层结果自动同步为系统标签（如"高价值会员""沉睡会员"），出现在用户标签列表的"系统标签"分组中，管理员可查看但不可手动删除。分层变化时标签自动更新。

#### 4.4.4 手动覆盖

| 规则 | 说明 |
|-|-|
| 操作入口 | 会员详情页 → 分层信息区 → "手动调整"按钮（详见4.1.5） |
| 优先级 | 手动覆盖 > 自动计算，覆盖期间自动计算结果不生效 |
| 有效期 | 默认30天，到期后恢复自动计算（可配置7-180天） |
| 事件推送 | 手动变更同样推送segment_change事件到规则引擎 |
| 取消覆盖 | 管理员可随时取消手动覆盖，恢复自动计算 |
| 覆盖标记 | 手动调整的分层在详情页标注"手动调整"标签 |

> 详细的分层配置交互流程见 6.8 分层配置流程。

### 4.5 入会管理

#### 4.5.1 入会审批

**入会流程：**

```
登录用户在用户端选择会员类型 → 填写入会申请表单
→ （如需缴费）在线支付会费
→ 提交入会申请 → 状态：待审批
→ 管理员在PC后台审批：
   ├─ 审批通过 → 用户状态变更为会员 → 生成会员卡 → 推送通知
   ├─ 审批拒绝 → 通知用户，说明拒绝原因
   └─ 需补充材料 → 通知用户补充
→ 审批通过后：
   ├─ 更新user_base.identity_status = member
   ├─ 创建user_member_ext记录（类型/等级/到期日/成长值初始值）
   ├─ 生成电子会员卡
   ├─ 推送identity_change事件 → 规则引擎
   ├─ 推送member.join事件 → 触发新会员欢迎系列
   └─ 写IdentityChangeLog
```

**审批配置：**

| 配置项 | 说明 |
|-|-|
| 审批模式 | 免审批（自动通过）/ 单人审批 / 双人审批 |
| 审批人 | 默认机构管理员，可指定子管理员 |
| 审批时限 | 超时自动通过/超时自动拒绝（可配置） |
| 批量审批 | 支持勾选多个申请批量通过/拒绝 |

**入会申请表单（按类型配置，配置方式见4.2.5）：**

系统字段（固定）：

| 字段 | 说明 | 是否必填 |
|-|-|-|
| 会员类型 | 选择要加入的会员类型 | 是 |
| 姓名 | 真实姓名 | 是 |
| 联系方式 | 手机号（已注册则自动填充） | 是 |
| 入会协议 | 签署入会协议（签名字段） | 是 |
| 会费支付 | 如需缴费，在线支付 | 按类型配置 |

自定义字段（按类型配置）：

| 字段 | 说明 | 是否必填 |
|-|-|-|
| 推荐人 | 部分类型要求填写推荐人 | 按类型配置 |
| 自定义字段 | 管理员在4.2.5配置页面中添加的字段（如职业、公司职位、学号等） | 按配置 |

> 每个会员类型的入会申请表单字段独立配置，用户端展示的表单内容随类型切换而变化。

#### 4.5.2 退会管理

**退会流程：**

```
场景A：会员主动退会
会员在用户端申请退会 → 选择退会原因 → 提交退会申请
→ 管理员审批（可选，按机构配置）
→ 审批通过/免审批：
   ├─ 更新user_base.identity_status = logged_in
   ├─ user_member_ext标记退会（status=withdrawn, withdrawn_at）
   ├─ 会员权益同步失效
   ├─ 会员卡标记失效
   ├─ 推送identity_change事件 → 规则引擎
   ├─ 推送member.leave事件 → 触发退会关怀系列
   └─ 写IdentityChangeLog

场景B：会费到期自动退会
会费到期 → 进入宽限期 → 宽限期结束未续费
→ 系统自动执行退会（同上流程，trigger=member_expire）

场景C：管理员强制退会
管理员在PC后台对会员执行"强制退会" → 需填写原因
→ 系统执行退会（同上流程，trigger=admin_cancel）
```

**退会规则：**

| 规则 | 说明 |
|-|-|
| 数据保留 | 退会后会员历史记录保留（活动参与、消费、积分等），不删除 |
| 权益失效 | 退会后所有会员权益即时失效（折扣/优惠券/专属活动等） |
| 积分处理 | 退会后积分保留但冻结，重新入会后解冻 |
| 会员卡 | 退会后会员卡标记"已失效" |
| 重新入会 | 退会后可重新申请入会，按新入会流程处理 |
| 会费退还 | 退会不退还会费（除非机构配置允许按比例退还） |
| 成长值 | 退会后成长值清零，重新入会从初始值开始 |

## 六、交互流程

### 6.1 入会流程

```
登录用户在用户端点击"加入会员"
→ 选择会员类型（展示类型名称/会费/权益对比）
→ 填写入会申请表单（按类型配置的字段）
→ 签署入会协议（签名字段）
→ （如需缴费）跳转支付页面 → 支付成功
→ 提交申请 → 状态：待审批
→ 管理员在PC后台收到入会申请通知
→ 审批：
   ├─ 通过 → 系统自动：
   │   ├─ user_base.identity_status → member
   │   ├─ 创建user_member_ext（类型/初始等级/到期日/成长值=0）
   │   ├─ 生成电子会员卡
   │   ├─ 推送identity_change + member.join事件
   │   └─ 推送入会成功通知（APP+短信）
   ├─ 拒绝 → 通知用户拒绝原因
   └─ 需补充 → 通知用户补充材料
```

### 6.2 退会流程

```
场景A：会员主动退会
→ 会员在用户端申请退会 → 选择退会原因
→ （按配置）管理员审批
→ 审批通过：
   ├─ user_base.identity_status → logged_in
   ├─ user_member_ext.member_status → withdrawn
   ├─ 会员权益失效
   ├─ 会员卡标记失效
   ├─ 推送identity_change + member.leave事件
   └─ 推送退会确认通知

场景B：会费到期自动退会
→ 会费到期 → 进入宽限期（保留权益，推送续费提醒）
→ 宽限期结束未续费 → 自动执行退会（同上，trigger=member_expire）
```

### 6.3 会员升级流程

```
会员产生行为（消费/活动/登录）→ 成长值累加
→ 系统检测成长值达到更高等级门槛
→ 执行晋级：
   ├─ 更新user_member_ext.member_level
   ├─ 触发升级礼包发放（优惠券/积分/赠品）
   ├─ 更新会员卡等级和卡面
   ├─ 推送晋级通知（APP+短信）"恭喜您升级为XX等级！"
   ├─ 推送member.level_up事件 → 规则引擎
   └─ 写LevelChangeLog
```

### 6.4 会员类型转换流程

```
会员/管理员发起类型转换申请
→ 选择目标类型（如：学生会员→个人会员）
→ 系统展示转换预览：
   ├─ 新会费标准（差额计算）
   ├─ 新等级映射
   └─ 新权益对比
→ （如需补差价）在线支付
→ 管理员审批
→ 审批通过：
   ├─ 更新user_member_ext.member_type
   ├<arg_value>desktop_name</arg_key><arg_value>cloud   ├─ 更新user_member_ext.member_type
   ├─ 等级按新类型体系重新映射
   ├─ 权益按新类型+新等级重新计算
   ├─ 会费按新标准计算（差额退补）
   ├─ 推送member.type_change事件
   └─ 写TypeChangeLog
```

### 6.5 会费续费流程

```
会费即将到期（到期前X天）
→ 系统推送续费提醒（短信/APP推送/社群消息）
→ 会员点击续费 → 在线支付
→ 支付成功：
   ├─ 更新user_member_ext.expired_at（延长到期日）
   ├─ 更新last_payment_at
   ├─ 更新会员卡到期时间
   └─ 推送续费成功通知

→ 未续费到期 → 进入宽限期
→ 宽限期内续费 → 恢复正常
→ 宽限期结束 → 自动退会
```

### 6.6 会员卡配置流程

```
管理员进入 会员管理 → 会员类型管理
→ 选择某个会员类型 → 点击"配置" → 切换到"会员卡"Tab
→ 页面布局（三栏式拖拽编辑器）：
   ├─ 左侧：卡面元素库（可拖拽到中间预览区）
   │   ├─ 基础元素：会员姓名、类型名称、等级名称、到期日、会员编号、机构Logo
   │   ├─ 装饰元素：背景图案、渐变色、几何图形、等级图标/勋章
   │   └─ 功能组件：动态二维码区域
   ├─ 中间：卡面实时预览区（所见即所得）
   │   ├─ 显示当前类型的基础卡面模板
   │   ├─ 元素可点击选中、拖拽调整位置和大小
   │   └─ 顶部Tab切换：类型模板 | 各等级差异化样式
   └─ 右侧：属性配置面板（选中元素后展示）
       ├─ 类型级配置：基础背景色系、Logo位置/大小、卡片比例、信息布局规则
       └─ 等级级配置：切换到某等级后配置——卡面图案、颜色深浅、等级标识、自定义卡面上传

→ 操作步骤：
   1. 先在"类型模板"Tab下配置基础卡面（拖拽元素、调整布局、设置底色）
   2. 切换到某个等级Tab，在类型模板基础上叠加差异化样式
   3. 可上传自定义卡面图片完全覆盖模板
   4. 实时预览效果
→ 保存 → 配置生效
→ 已入会会员的会员卡在下次打开时更新为最新样式
```

### 6.8 分层配置流程

```
管理员进入 会员管理 → 会员分层管理 → 点击"分层配置"按钮
→ 页面布局（三栏式配置界面）：

   ├─ 左侧：参数分类导航
   │   ├─ 指标模板选择（首次配置时展示）
   │   │   ├─ 交易型（有商城/收费活动）— R:最近消费/F:消费次数/M:消费金额
   │   │   ├─ 活动型（纯社团/协会）— R:最近活动参与/F:活动次数/M:活动贡献度
   │   │   └─ 自定义 — 自由组合可选指标池
   │   └─ 参数分类导航树：
   │       ├─ 指标配置（模板选择 + 各维度指标选择，自定义模板时展开）
   │       ├─ 维度权重（R/F/M权重分配）
   │       ├─ R评分阈值（5档阈值）
   │       ├─ F评分阈值（5档阈值）
   │       ├─ M评分阈值（5档阈值，单位随指标模板变化）
   │       ├─ 分层定义（各分层得分区间+名称）
   │       └─ 计算周期（观察期/频率/沉睡覆盖天数）
   │
   ├─ 中间：实时预览区
   │   ├─ 上半部分：当前分层分布（饼图 + 人数列表）
   │   │   — 展示各分层当前人数和占比
   │   │   — 例：高价值15%(46人) / 潜力22%(68人) / 稳定35%(108人) / 沉睡18%(56人) / 流失10%(31人)
   │   ├─ 下半部分：配置变更影响预览
   │   │   — 修改任意参数后，系统实时按新配置重新计算全量会员分层
   │   │   — 展示新旧分布对比表：各分层人数变化（+/-）和迁移矩阵
   │   │   — 迁移矩阵示例：
   │   │     |  | 新-高价值 | 新-潜力 | 新-稳定 | 新-沉睡 | 新-流失 |
   │   │     |---|---|---|---|---|---|
   │   │     | 旧-高价值 | 46 | 3 | 0 | 0 | 0 |
   │   │     | 旧-潜力 | 5 | 60 | 3 | 0 | 0 |
   │   │     | 旧-稳定 | 0 | 8 | 95 | 5 | 0 |
   │   │     | 旧-沉睡 | 0 | 0 | 12 | 44 | 0 |
   │   │     | 旧-流失 | 0 | 0 | 0 | 7 | 24 |
   │   │   — 高亮变化最大的分层（如"沉睡会员将增加12人"）
   │   └─ 顶部提示条："以上为预览效果，修改参数后实时刷新，保存后正式生效"
   │
   └─ 右侧：参数编辑面板（选中左侧某参数分类后展示对应编辑区）
       ├─ 指标模板配置（选中"指标配置"时）：
       │   ├─ 模板选择单选：交易型 / 活动型 / 自定义
       │   ├─ 选择"自定义"时展开各维度指标选择器：
       │   │   ├─ R维度：下拉选择统计指标（最近消费/最近活动/最近登录/最近互动）
       │   │   ├─ F维度：多选统计指标 + 每个指标权重滑块
       │   │   └─ M维度：多选统计指标 + 每个指标权重滑块（金额类直接相加，积分类按比例折算）
       │   └─ 模板切换提示："切换模板将重置评分阈值，确认切换？"
       │
       ├─ 维度权重配置（选中"维度权重"时）：
       │   ├─ R权重滑块（10%-80%）+ 数值输入框
       │   ├─ F权重滑块（10%-80%）+ 数值输入框
       │   ├─ M权重（自动计算 = 100% - R - F，只读展示）
       │   ├─ 实时校验：三权重之和=100%，不满足标红提示"权重之和必须为100%"
       │   └─ 每个维度下方显示当前所选指标说明
       │
       ├─ 评分阈值配置（选中"R/F/M评分阈值"时）：
       │   ├─ 5档阈值输入框（阈值单位随指标模板自动适配）
       │   ├─ 交易型M维度显示"HKD"，活动型M维度显示"分"
       │   ├─ 实时校验：R阈值必须递减，F/M阈值必须递增，不满足标红
       │   └─ 每档旁边显示当前该档人数（如"R=5分: 326人"），辅助判断阈值合理性
       │
       ├─ 分层定义配置（选中"分层定义"时）：
       │   ├─ 各分层得分阈值输入框（高价值≥4.0 / 潜力≥3.0 / 稳定≥2.0 / 沉睡≥1.0）
       │   ├─ 分层名称可编辑（如"高价值"可改为"核心会员"）
       │   ├─ 实时校验：阈值必须递减
       │   └─ 流失会员固定条件（R=1且F=1且M=1），灰色展示不可编辑
       │
       └─ 计算周期配置（选中"计算周期"时）：
           ├─ RFM观察期天数输入框（30-365天）
           ├─ 计算频率单选：每日 / 每周 / 每月
           └─ 沉睡覆盖天数输入框（7-180天）

→ 操作步骤：
   1. 首次配置：选择指标模板（交易型/活动型/自定义），自定义模板时选择各维度统计指标
   2. 在左侧参数分类导航中选择要编辑的参数类别
   3. 在右侧面板修改具体参数值
   4. 修改后中间预览区实时刷新，展示按新配置重新计算后的分层分布变化和迁移矩阵
   5. 检查迁移矩阵，确认变化符合预期（如"沉睡增加12人"是否可接受）
   6. 如需调整其他参数，重复步骤2-5
   7. 点击"保存"→ 系统弹出确认框：
      ├─ 展示配置变更摘要（改了哪些参数，旧值→新值）
      ├─ 展示影响预览摘要（各分层人数变化 +N/-N）
      └─ 选择生效方式：
          ├─ 下次计算周期自动生效（默认，推荐）
          └─ 立即重新计算（谨慎操作，大量会员分层将变化，事件批量推送）
   8. 确认保存 → 配置写入SegmentConfig表
   9. 按选择的生效方式执行：等待下次计算周期 / 立即触发批量重算
   10. 重算完成后，系统自动执行：
       ├─ 分层结果更新到 user_member_ext.rfm_layer
       ├─ 分层标签同步更新（系统标签自动刷新）
       ├─ 分层变化写入 LayerChangeLog
       ├─ segment_change事件批量推送到规则引擎（限流：100条/秒）
       └─ 规则引擎消费事件 → 触发对应自动化运营动作（如沉睡唤醒/回归欢迎/高价值识别）
```

## 七、异常与边界

| 异常场景 | 处理方式 |
|-|-|
| 入会申请审批超时 | 按配置自动通过或自动拒绝，通知管理员 |
| 会费支付失败 | 入会申请暂存，提示用户重新支付，支付成功后继续审批 |
| 等级晋级时成长值计算异常 | 保留原等级，记录异常日志，人工介入 |
| 类型转换时等级无法映射 | 默认降为新类型最低等级，通知管理员人工调整 |
| 批量入会审批部分失败 | 成功的正常处理，失败的标注原因，汇总报告 |
| 退会时存在未完成订单 | 提示"存在未完成订单，请先处理后再退会" |
| 会员卡二维码被截图 | 二维码每60秒刷新，截图后1分钟失效 |
| 升级礼包发放失败 | 重试3次，仍失败则记录日志，管理员可手动补发 |
| 宽限期内部分缴费 | 按比例延长到期日（如缴半年费→延长6个月） |

## 九、验收标准

### 9.1 P0验收标准

**AC-MEMBER-01：入会流程**

```
Given: 用户A（用户状态=logged_in）在用户端选择"个人会员"类型提交入会申请
When: 管理员在PC后台审批通过
Then: 
  - user_base.identity_status 变为 member
  - user_member_ext 创建记录（type=个人, level=初始等级, growth_value=0）
  - 生成电子会员卡
  - identity_change事件推送
  - member.join事件推送
  - 用户A收到入会成功通知
```

**AC-MEMBER-02：退会流程**

```
Given: 会员B（用户状态=member）申请退会
When: 管理员审批通过退会
Then:
  - user_base.identity_status 回退为 logged_in
  - user_member_ext.member_status = withdrawn
  - 会员权益全部失效
  - 会员卡标记"已失效"
  - identity_change事件推送
  - member.leave事件推送
```

**AC-MEMBER-03：会员档案**

```
Given: 管理员进入会员C的详情页
When: 查看会员档案
Then: 页面展示基本信息+会员信息（类型/等级/到期日）+分层信息+标签+行为时间线+自定义字段
```

**AC-MEMBER-04：标签管理**

```
Given: 管理员创建自定义标签"理事会成员"
When: 给会员D打上"理事会成员"标签
Then: 会员D的标签列表显示"理事会成员"，用户列表可按该标签筛选
```

**AC-MEMBER-05：手动分层调整**

```
Given: 会员E当前分层为"活跃"（自动计算）
When: 管理员手动调整为"高价值"，备注"核心客户"
Then: 
  - 会员E分层显示"高价值"并标注"手动调整"
  - LayerChangeLog记录变更
  - 自动计算暂停，直到管理员取消手动覆盖
```

### 9.2 P1验收标准

**AC-MEMBER-06：等级晋级**

```
Given: 会员F当前等级VIP1，成长值990
When: 会员F参与一次活动（+10成长值），成长值达到1000
Then: 
  - 自动晋级为VIP2
  - 触发升级礼包发放
  - 会员卡更新为VIP2卡面
  - 推送晋级通知
  - LevelChangeLog记录
```

**AC-MEMBER-07：等级降级**

```
Given: 会员G为VIP3，保级周期365天需获取≥2000成长值
When: 保级周期到期，实际获取1500成长值
Then: 
  - 到期前30天推送降级预警
  - 到期日自动降级为VIP2
  - 权益调整为VIP2权益
  - 推送降级通知
```

**AC-MEMBER-08：会员类型转换**

```
Given: 会员H为"学生会员"
When: 提交类型转换为"个人会员"申请，管理员审批通过
Then:
  - member_type更新为"个人会员"
  - 等级按新类型体系映射
  - 会费按新标准计算
  - 权益按新类型+新等级重新计算
  - TypeChangeLog记录
```

**AC-MEMBER-09：会费续费**

```
Given: 会员I会费将于7天后到期
When: 系统检测到期临近
Then: 
  - 提前7天推送续费提醒
  - 会员在线支付续费成功后，expired_at延长1年
  - 若到期未续费，进入宽限期，宽限期结束自动退会
```

### 9.3 性能要求

| 指标 | 要求 |
|-|-|
| 入会审批处理 | <3秒（含状态变更+事件推送） |
| 会员档案查询 | <2秒（含聚合多维度数据） |
| 等级晋级检测 | 实时（成长值变更后即时检测） |
| 保级周期检查 | 每日定时任务，万级会员<5分钟 |
| 会员卡二维码刷新 | 每60秒 |
| 分层调整 | <1秒 |

## 附录：与其他模块的接口约定

| 接口 | 提供给 | 格式 |
|-|-|-|
| 查询会员信息 | 活动管理/商城/优惠券 | `GET /members/{user_id}` → `{member_type, member_level, expired_at, ...}` |

| 查询分层结果 | 数据分析/规则引擎 | `GET /members/{user_id}/layer` → `{current_layer, layer_source, last_changed_at}` |
