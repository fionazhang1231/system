# 连心用户表与会员表字段设计

> 版本：v1  
> 日期：2026-08-04  
> 依据：多轮产品讨论结论 + 需求文档现有数据模型 + 行业最佳实践

---

## 一、设计原则

1. **垂直拆分**：用户主表（高频字段）+ 会员扩展表（低频字段），1:1关联，避免宽表
2. **内置字段 vs 自定义字段分离**：内置字段管"系统能运转必须有的"，自定义字段管"每个机构想额外采集的"
3. **手机号为业务主标识**：user_id为物理主键，手机号为业务唯一键
4. **软删除**：注销不物理删除，标记状态保留审计记录

---

## 二、表结构设计

### 2.1 user_base（用户主表）

> 管理所有注册用户，含登录用户、已注销用户。对应后台「用户管理」菜单。

| 序号 | 字段名 | 类型 | 必填 | 说明 |
|------|--------|------|------|------|
| 1 | id | BIGINT | ✅ | 主键，自增 |
| 2 | phone | VARCHAR(20) | ✅ | 手机号（业务唯一键，唯一索引） |
| 3 | phone_region | VARCHAR(8) | ✅ | 区号（+852/+86等） |
| 4 | email | VARCHAR(100) | | 邮箱 |
| 5 | password_hash | VARCHAR(255) | | 密码哈希（支持空密码=纯验证码登录） |
| 6 | name | VARCHAR(50) | | 姓名/昵称 |
| 7 | avatar_url | VARCHAR(500) | | 头像URL |
| 8 | gender | TINYINT | | 性别（0=未知 1=男 2=女） |
| 9 | birthday | DATE | | 生日 |
| 10 | identity_status | ENUM | ✅ | 身份状态：guest/logged_in/member |
| 11 | registered_at | TIMESTAMP | ✅ | 注册时间 |
| 12 | registered_channel | ENUM | ✅ | 注册来源：app/h5/mini_app/web |
| 13 | last_login_at | TIMESTAMP | | 最后登录时间 |
| 14 | last_login_channel | ENUM | | 最后登录渠道 |
| 15 | status | ENUM | ✅ | 账号状态：active/deleted/merged |
| 16 | deleted_at | TIMESTAMP | | 注销时间（status=deleted时记录） |
| 17 | merged_into_user_id | BIGINT | | 合并目标用户ID（status=merged时记录） |
| 18 | org_id | BIGINT | ✅ | 所属机构ID |
| 19 | created_at | TIMESTAMP | ✅ | 创建时间 |
| 20 | updated_at | TIMESTAMP | ✅ | 更新时间 |

**索引设计：**
- PRIMARY: id
- UNIQUE: phone（软删除后解绑，允许重新注册）
- INDEX: org_id + identity_status
- INDEX: org_id + status
- INDEX: registered_channel

**字段数：20个（符合≤30字段的高并发规范）**

### 2.2 user_member_ext（会员扩展表）

> 管理会员特有信息，1:1关联user_base。对应后台「会员管理」菜单。仅identity_status=member的用户有记录。

| 序号 | 字段名 | 类型 | 必填 | 说明 |
|------|--------|------|------|------|
| 1 | id | BIGINT | ✅ | 主键 |
| 2 | user_id | BIGINT | ✅ | 外键→user_base.id（唯一索引） |
| 3 | member_no | VARCHAR(32) | ✅ | 会员编号（机构内唯一） |
| 4 | member_type | VARCHAR(20) | ✅ | 会员类型：individual/group/student/honorary |
| 5 | member_level | VARCHAR(20) | | 会员等级：VIP1~VIP5（按类型内等级体系） |
| 6 | join_date | DATE | ✅ | 入会日期 |
| 7 | expire_date | DATE | | 到期日期（永久会员为空） |
| 8 | membership_status | ENUM | ✅ | 会员状态：active/expired/revoked |
| 9 | rfm_layer | VARCHAR(20) | | 当前RFM分层：high_value/potential/stable/sleeping |
| 10 | rfm_score | DECIMAL(3,1) | | 当前RFM得分（0.0~5.0） |
| 11 | rfm_manual_override | TINYINT(1) | | 是否手动覆盖分层（0=自动 1=手动） |
| 12 | rfm_override_expire | DATE | | 手动覆盖有效期（到期恢复自动计算） |
| 13 | approved_by | BIGINT | | 审批人user_id |
| 14 | approved_at | TIMESTAMP | | 审批通过时间 |
| 15 | growth_value | INT | | 成长值（用于等级晋级判定） |
| 16 | remark | TEXT | | 备注 |
| 17 | created_at | TIMESTAMP | ✅ | 创建时间 |
| 18 | updated_at | TIMESTAMP | ✅ | 更新时间 |

**索引设计：**
- PRIMARY: id
- UNIQUE: user_id
- INDEX: member_type + membership_status
- INDEX: member_level
- INDEX: rfm_layer
- INDEX: org_id（通过JOIN user_base获取）

**字段数：18个（符合≤30字段规范）**

### 2.3 user_identity（用户标识表）

> 存储用户的跨渠道登录标识。一个user_id可对应多条记录（手机号、微信OpenID等）。

| 序号 | 字段名 | 类型 | 必填 | 说明 |
|------|--------|------|------|------|
| 1 | id | BIGINT | ✅ | 主键 |
| 2 | user_id | BIGINT | ✅ | 外键→user_base.id |
| 3 | provider | ENUM | ✅ | 标识来源：phone/wechat_miniapp/wechat_h5/app |
| 4 | provider_uid | VARCHAR(128) | ✅ | 外部标识值（手机号/OpenID等） |
| 5 | is_primary | TINYINT(1) | ✅ | 是否主标识（手机号=1，其他=0） |
| 6 | created_at | TIMESTAMP | ✅ | 绑定时间 |

**索引设计：**
- PRIMARY: id
- UNIQUE: provider + provider_uid（同一标识不可绑两个user_id）
- INDEX: user_id

**说明：**
- 用户注销时，phone标识解绑（is_primary保持但标记unbind），允许该手机号重新注册
- OpenID标识保留但标记inactive，防止冒用
- 管理员不需要操作此表，系统自动维护

### 2.4 custom_field_definition（自定义字段定义表）

> 管理员配置，每个机构可自定义最多30个字段。

| 序号 | 字段名 | 类型 | 必填 | 说明 |
|------|--------|------|------|------|
| 1 | id | BIGINT | ✅ | 主键 |
| 2 | org_id | BIGINT | ✅ | 所属机构 |
| 3 | field_key | VARCHAR(50) | ✅ | 英文标识（如occupation），机构内唯一 |
| 4 | field_name | VARCHAR(50) | ✅ | 显示名称（如"职业"） |
| 5 | field_type | ENUM | ✅ | 字段类型（见下方类型表） |
| 6 | options | JSON | | 单选/多选的选项列表 |
| 7 | is_required | TINYINT(1) | ✅ | 是否必填（注册/入会时） |
| 8 | is_searchable | TINYINT(1) | ✅ | 是否可搜索（出现在列表筛选条件） |
| 9 | visibility | ENUM | ✅ | 可见性：admin_only/user_visible/public |
| 10 | sort_weight | INT | ✅ | 排序权重（详情页显示顺序） |
| 11 | is_active | TINYINT(1) | ✅ | 是否启用（可停用不可删除） |
| 12 | max_size | INT | | 附件类型专用：最大上传大小（MB） |
| 13 | allowed_ext | JSON | | 附件类型专用：允许的文件扩展名 |
| 14 | created_at | TIMESTAMP | ✅ | 创建时间 |
| 15 | updated_at | TIMESTAMP | ✅ | 更新时间 |

### 2.5 自定义字段类型（完整版）

| 类型 | 说明 | 示例 | 存储方式 |
|------|------|------|---------|
| text | 单行文本 | 职业、公司名称 | VARCHAR(500) |
| textarea | 多行文本 | 备注、简介 | TEXT |
| number | 数值 | 年收入、身高 | DECIMAL |
| date | 日期选择 | 生日、入会日期 | DATE |
| select | 单选下拉 | 性别、学历 | 存option_id |
| multi_select | 多选下拉 | 兴趣领域、专长 | JSON数组存option_id |
| boolean | 是/否 | 是否志愿者 | TINYINT(1) |
| **attachment** | **附件上传** | **证件照片、会员申请表、音频/视频** | **JSON（文件URL+文件名+大小+类型）** |
| **signature** | **在线签名** | **入会协议签名、授权签名** | **VARCHAR(500)（签名图片URL）** |

**附件类型说明：**
- 支持上传图片（jpg/png/gif）、文件（pdf/doc/excel）、音频（mp3/wav）、视频（mp4）
- 可配置最大上传大小和允许的文件扩展名
- 存储为JSON：`{"url": "https://...", "filename": "xxx.pdf", "size": 1024, "mime": "application/pdf"}`
- 支持多文件上传（JSON数组）

**签名类型说明：**
- 用户在App/H5/小程序上手写签名，生成签名图片
- 存储为签名图片URL + 签名时间戳
- 主要用于入会协议签署、授权确认等场景
- 存储为JSON：`{"sign_url": "https://...", "signed_at": "2026-08-04T15:00:00+08:00"}`

## 三、表关系图

```
user_base（用户主表）
  ├── 1:1 → user_member_ext（会员扩展表，仅会员有）
  ├── 1:N → user_identity（用户标识表，多渠道标识）
  ├── 1:N → user_custom_field（自定义字段值）
  ├── 1:N → identity_change_log（身份变更日志）
  └── 1:N → user_merge_log（合并日志，作为source或target）

custom_field_definition（自定义字段定义）
  └── 1:N → user_custom_field（自定义字段值）
```

## 四、后台菜单与数据表映射

| 后台菜单 | 数据来源 | 说明 |
|---------|---------|------|
| 用户管理 > 用户列表 | user_base WHERE status != 'merged' | 所有注册用户 |
| 用户管理 > 已注销用户 | user_base WHERE status = 'deleted' | 已注销用户 |
| 用户管理 > 用户详情 | user_base + user_identity | 基本信息+登录渠道 |
| 用户管理 > 手机号变更 | UPDATE user_base.phone + user_identity | 管理员协助换绑 |
| 用户管理 > 账号注销 | UPDATE user_base SET status='deleted' | 软删除 |
| 用户管理 > 用户合并 | INSERT user_merge_log + UPDATE user_base | 合并重复账号 |
| 会员管理 > 会员列表 | user_base JOIN user_member_ext WHERE identity_status='member' | 已审批会员 |
| 会员管理 > 会员详情 | user_base + user_member_ext + user_custom_field | 完整会员视图 |
| 会员管理 > 会员类型管理 | user_member_ext.member_type + 配置表 | 类型配置 |
| 会员管理 > 会员等级管理 | user_member_ext.member_level + 配置表 | 等级配置 |
| 会员管理 > 会员分层管理 | user_member_ext.rfm_layer + 配置表 | RFM分层 |
| 会员管理 > 入会管理 | user_base WHERE identity_status='logged_in' + 审批流 | 入会审批 |

## 五、关键业务规则

### 5.1 手机号与账号

| 规则 | 说明 |
|------|------|
| 手机号注册 | 一个手机号注册一个user_id，绑定到user_identity |
| 手机号换绑 | 用户自助或管理员协助，验证旧号后绑定新号，user_id不变 |
| 账号注销 | 软删除，status=deleted，手机号从user_identity解绑 |
| 重新注册 | 同一手机号可重新注册，生成新user_id，与旧账号数据隔离 |
| 旧账号恢复 | 管理员可恢复已注销账号，清除deleted标记，手机号重新绑定 |

### 5.2 跨渠道身份关联

| 场景 | 流程 |
|------|------|
| App/H5注册 | 手机号+验证码 → 生成user_id → user_identity写入phone |
| 小程序首次登录 | 获取OpenID → 引导授权手机号 → 查user_base匹配phone → 匹配则关联OpenID到该user_id，不匹配则新建 |
| 小程序再次登录 | 获取OpenID → 查user_identity找到user_id → 直接登录 |

### 5.3 自定义字段约束

| 约束 | 说明 |
|------|------|
| 数量上限 | 每个机构最多30个自定义字段 |
| 标识唯一 | 同一机构内field_key不可重复 |
| 类型不可变更 | 字段创建后类型不可修改（避免数据不兼容） |
| 可停用不可删除 | 字段可停用（不展示不校验），历史数据保留 |
| 附件大小 | 单文件默认上限10MB，可配置 |
| 签名存储 | 签名图片存储到OSS，字段值记录URL+签名时间 |

## 六、与原需求文档的差异说明

| 变更项 | 原设计 | 新设计 | 原因 |
|--------|--------|--------|------|
| 用户表结构 | 单表User含所有字段 | user_base + user_member_ext垂直拆分 | 避免宽表，符合行业规范 |
| 会员字段位置 | 散落在User表和事件payload | 独立user_member_ext表 | 会员字段低频，拆分提升查询效率 |
| 自定义字段类型 | 7种（文本/长文本/数字/日期/单选/多选/布尔） | 9种（新增附件、签名） | 满足证件上传、协议签署场景 |
| 注销策略 | 未明确 | 软删除+手机号可重新注册 | 对齐有赞/淘宝，不流失换号用户 |
| 跨渠道身份 | 手机号+UnionID/OpenID | 手机号为主+OpenID辅助（不需要UnionID） | 连心只有一个小程序，不需要UnionID |
| 身份标识表 | 无独立标识表 | 新增user_identity表 | 解耦用户主表与登录渠道标识 |
